## 什么是 Dot Skill？

Dot Skill 为 AI 助手提供统一方式来使用 Dot. 设备。你可以列出设备、查看状态、显示文本或图像、切换内容、设计 Canvas 画面以及更新设备设置，而不必手写每一个请求。

它提供三种集成方式：

- 供能够发现 `SKILL.md` 的 agent 使用的可移植 Agent Skill
- 通过本地 stdio 运行、包含固定设备工具的 MCP Server
- 供 GPT Actions 和其他 OpenAPI 兼容客户端使用的 OpenAPI schema

## 你可以做什么

- 在设备上显示文本、图像和 Canvas 布局
- 为 API 内容设置任务别名，方便在设备任务列表中识别
- 查看电量、Wi-Fi、显示和渲染状态
- 读取或更新设备设置及时区
- 列出循环任务或固定任务中的内容
- 切换到下一个内容
- 在发送 Canvas 前先在本地校验 payload

## 集成状态

| 平台 | 状态 | 集成方式 |
| --- | --- | --- |
| Codex | Supported | 从本仓库 marketplace 安装 Codex plugin |
| OpenAI GPT Actions | Supported via OpenAPI | 导入 `openapi/dot-openapi.yaml` 并配置 Bearer 认证 |
| Claude Code、CodeBuddy、Cursor、VS Code Copilot、Kimi Code | Experimental | 使用 canonical skills 和本地 stdio MCP 配置 |
| Hermes、OpenCode、Gemini CLI、Goose | Experimental | 将 `dot-mcp` 注册为本地 stdio Server |
| Trae、MiniMax Code、DeepSeek Harness | Experimental | 按仓库中的 MCP-first 配置说明接入 |
| Remote MCP 和 MCP Registry | Planned | 尚未确定发布时间 |

`Experimental` 表示仓库已提供可移植 Skill 或 MCP 配置，但这里尚未完成对应平台的真实 smoke test。

## 前提条件

- 一个 Dot. 账号和至少一台设备
- 一个 Dot. API key
- Python 3.10+，用于辅助脚本或本地 MCP Server
- `pipx` 或 `uvx`，用于安装或运行 MCP Server

开始前，请先获取[API key](/docs/service/open/get_api)和[设备序列号](/docs/service/open/get_device_id)。

## 本地 MCP Server

本地 Server 与 agent 在同一台设备上通过 stdio 通信。它从进程环境中的 `DOT_API_KEY` 读取密钥，不会把密钥作为工具参数接收，也不提供任意 HTTP 访问。

安装一次：

```bash
pipx install git+https://github.com/MindReset/dot_skill.git
```

或按需运行：

```bash
uvx --from git+https://github.com/MindReset/dot_skill.git dot-mcp
```

在启动 agent 的同一环境中设置 API key：

```bash
export DOT_API_KEY="dot_app_<your_api_key>"
```

仓库提供 Claude Code、CodeBuddy、Cursor、VS Code、Kimi Code、Hermes、OpenCode、Gemini CLI、Goose、Trae、MiniMax Code 和 DeepSeek Harness 的[配置示例](https://github.com/MindReset/dot_skill/blob/main/docs/mcp-configs.md)。

### MCP 工具

只读工具：

- `dot_list_devices`
- `dot_get_device_status`
- `dot_get_device_settings`
- `dot_list_timezones`
- `dot_list_tasks`
- `dot_validate_canvas`

会改变设备状态的工具：

- `dot_update_device_settings`
- `dot_switch_next_content`
- `dot_send_text`
- `dot_send_image`
- `dot_send_canvas`

MCP 写入请求只发送一次，不会自动重试。如果写入后发生网络错误，请先查看设备状态或任务列表，再决定是否重新发送。

<Callout type="warning">
不要把 API key 放进 prompt、工具参数、plugin manifest 或提交到仓库的 MCP 配置文件。
</Callout>

## Agent Skill 安装

### Codex plugin

将仓库添加为 Codex marketplace：

```bash
codex plugin marketplace add git@github.com:MindReset/dot_skill.git
```

然后安装 plugin：

```bash
codex plugin add dot-skill@mindreset-dot-skill
```

安装后请新建一个 Codex 线程，以便 Codex 加载 skills。

### 使用 `npx skills add`

安装两个 skill：

```bash
npx skills add https://github.com/MindReset/dot_skill.git
```

仅安装设备交互能力：

```bash
npx skills add https://github.com/MindReset/dot_skill.git --skill dot-device-openapi
```

仅安装 Canvas 设计能力：

```bash
npx skills add https://github.com/MindReset/dot_skill.git --skill dot-canvas-designer
```

旧的 `dot-openapi` 入口仍作为兼容路由保留。新安装建议使用 `dot-device-openapi` 和 `dot-canvas-designer`。

## OpenAPI 集成

导入 schema：

```text
https://raw.githubusercontent.com/MindReset/dot_skill/main/openapi/dot-openapi.yaml
```

配置 Bearer 认证：

```http
Authorization: Bearer dot_app_<your_api_key>
```

该 schema 覆盖设备发现、状态、设置、时区、任务列表、内容切换，以及 Text、Image 和 Canvas API 内容。

## API 与 payload 限制

- 服务速率限制为每秒 10 个请求。
- Text、Image 和 Canvas 写入要求对应的 API content item 已经存在于 Dot. App 内容工坊的设备循环任务中。
- 设备设置 interval 必须在 60,000 到 43,200,000 毫秒之间，并使用整分钟倍数。
- Canvas `data` 最大 64 KB，`windowData` 最大 128 KB，`layoutFull` 最大 8 KB。
- Canvas 布局最多包含 80 个元素，最大嵌套深度为 16。
- Canvas 字符串最大长度为 4,000 个字符。
- `taskAlias` 应放在 Text、Image 和 Canvas 请求的顶层，不要放进 Canvas `data`。

## 错误与排查

- `401`：确认启动 agent 的进程环境设置了 `DOT_API_KEY`，且 key 有效。
- `404`：检查设备序列号，并确认对应的内容任务存在。
- `429`：遵守每秒 10 个请求的限制，在速率窗口结束后再有意重试。
- Canvas 校验错误：先调用 `dot_validate_canvas`，或使用 `send_canvas.py --dry-run`。
- Text、Image 或 Canvas 任务错误：确认对应的 API content item 已存在于设备循环任务中。

## 辅助脚本

仓库提供列出设备、查看状态、读取或更新设置、列出任务、切换内容以及发送 Text、Image、Canvas payload 的 Python 脚本。脚本从环境变量读取 `DOT_API_KEY`，并与 MCP Server 使用相同的客户端和 Canvas 校验规则。
