## 显示屏模式

显示屏模式可以让支持该功能的工具通过同一个局域网向 Rand/0 的电子墨水屏发送自定义画面。设备屏幕尺寸为 `200 × 200` 像素，支持黑白和四灰阶画面。

<Callout type="warn" title="使用前请注意">
显示屏模式仅在局域网内可用，不提供额外的登录验证。请只在你信任的 Wi-Fi 网络中使用，并避免发送敏感内容。
</Callout>

## 使用前准备

开始前，请确认：

1. 已通过 [Wi-Fi](/docs/rand_0/start/wifi) 连接过一次网络，让 Rand/0 记住可用的 Wi-Fi 网络；
2. 设备电量充足，或已插入电源。电量过低时，设备会拒绝进入显示屏模式；
3. 用于发送画面的手机或电脑，与 Rand/0 连接到同一个局域网；
4. 已准备好支持 Rand/0 显示屏模式的工具。

## 进入显示屏模式

默认入口为：

- 主菜单 → **更多** → **显示屏** → 确认。

如果你自定义过桌面，请在当前桌面中找到 **显示屏**。

设备重启后会自动连接已记忆的 Wi-Fi。连接成功后，屏幕中央会显示设备 IP 地址。

就绪页面还会显示一个二维码，扫描后可以打开本显示屏模式指南，查看连接方式与协议说明。

## 连接并发送画面

1. 打开支持 Rand/0 显示屏模式的工具。
2. 输入设备屏幕上显示的 IP 地址并发起连接。
3. 按工具的提示选择画面并发送到 Rand/0。

显示屏模式一次只允许一个工具连接。新的连接建立后，之前的连接会自动断开。

<Callout type="info" title="关于连接工具">
显示屏模式负责让 Rand/0 接收局域网中的画面。你仍需要使用支持该功能的工具完成连接和推送，不同工具的具体操作方式可能不同。
</Callout>

<Callout type="info" title="官方示例">
你可以使用 GitHub 上的[官方 Rand/0 显示屏模式示例](https://github.com/MindReset/dot_open_platform/tree/main/capabilities/rand_0_display_mode)。它是一个无需额外依赖的浏览器工具，可以发送画面并接收设备按键事件。
</Callout>

## 按键操作

| 操作 | 作用 |
| --- | --- |
| 短按上键或下键 | 将对应的按键事件发送给当前连接的工具 |
| 长按上键 | 退出显示屏模式，并重启回到正常模式 |

电子墨水屏的刷新速度有限，更适合静态画面。连续推送画面时，设备只会保留最新画面，中间画面可能不会显示。

退出显示屏模式后，设备会回到正常模式。如果设备发生异常复位，也不会再次自动进入显示屏模式。

## 兼容工具协议

显示屏模式会在设备局域网 IP 上提供以下 WebSocket 端点：

| 端点 | 二进制帧 | 格式 |
| --- | ---: | --- |
| `ws://<IP>/display/bw` | 必须正好 5,000 字节 | 每像素 1 bit，黑白 |
| `ws://<IP>/display/gray4` | 必须正好 10,000 字节 | 每像素 2 bit，四灰阶 |

每张图片发送一个二进制帧。像素按从左到右、从上到下的行顺序排列，高位代表最左侧像素。黑白模式中，`1` 为白色、`0` 为黑色；四灰阶模式中，`00` 为白色、`01` 为浅灰、`10` 为深灰、`11` 为黑色。

同一时间只允许一个客户端连接，新连接会替换旧连接。如果图片发送速度快于屏幕刷新速度，设备只保留最新一帧。

设备会通过文本 JSON 发送按键事件和错误。例如：

```json
{"type":"key","key":"up","action":"short"}
```

二进制类型或长度不正确时，会返回 `expected_binary_5000` 或 `expected_binary_10000` 等错误。

## 常见提示

| 屏幕提示 | 处理方式 |
| --- | --- |
| 请插入电源 | 连接电源后再试，或等待设备电量充足。 |
| 无已记忆 Wi-Fi | 先通过 [Wi-Fi](/docs/rand_0/start/wifi) 连接一次网络，让设备记住可用网络。 |
| Wi-Fi 连接失败 / 无法获取 IP | 检查已记忆的 Wi-Fi 是否可用，并确认设备处于网络覆盖范围内。 |
| WebSocket 启动失败 | 退出后重启设备，再重新进入显示屏模式。 |
