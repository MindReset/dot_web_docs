After [submitting a stable version](/docs/service/open/organization_software/publish), open the version under **Software** in your organization to follow its review. You can also [get the version details](/docs/service/open/organization_software/organization_versions) with an organization credential. An approved stable version goes live automatically.

## Respond to a review on the website

- A stable draft moves to **In review** when you select **Submit for review**. Select **Withdraw submission** to return it to draft.
- When the status is **Changes requested**, read the review feedback and select **Edit and resubmit**. You can update the notes, keep or replace files, and resubmit the same version.

## Resubmit with the organization API

If a stable version enters the `rejected` state, [get its details](/docs/service/open/organization_software/organization_versions) to read `reviewReason`, `id`, and the current `reviewId`. Prepare another upload with the original `firmwareId` and `version`. Set `revision.versionId` to the version’s `id` and `revision.reviewId` to its current review ID.

Set `revision.retainFiles` to an array of file types to keep, such as `["ota", "merged"]`. Put new and replacement files in `artifacts`. Use `[]` to replace all files. The submitted version must include at least one file. If you only keep existing files, preparation returns an empty `uploads` object and you can go straight to completion.

The request’s `releaseNotes` replaces the entire set of notes. Send the existing text again for any language you want to keep. Completion returns the original version `id`, `state: "pending"`, and a new `reviewId` for the next review.

When you receive the new `uploadId`, follow the [upload steps](/docs/service/open/organization_software/upload) for any files in `uploads`, then complete the upload. If you receive `409 ORGANIZATION_SOFTWARE_STATE_CHANGED`, get the version details again and use the current `reviewId`.
