組織の認証情報を使うと、自分の組織の Read Pico ソフトウェアを照会・アップロード・公開し、デバイスソフトウェア ID を作成・アーカイブできます。オーナーと管理者は、`Field Lab` の「組織 → 認証情報」で API キーと OAuth クライアントを作成できます。

## API キーを作成する

1. 「API キー → API キーを作成」を選び、名前に `Field Lab Integration` を入力します。
2. キーをコピーして、サーバー側のシークレット管理ツールに保存します。キーの全体が表示されるのは作成時の一度だけです。
3. キーを交換する場合は、新しいキーを作成し、利用先を更新してから古いキーを無効にします。

## OAuth クライアントを作成する

1. 「OAuth クライアント → OAuth クライアントを作成」を選び、名前に `Field Lab Service` を入力します。
2. クライアント ID とクライアントシークレットをコピーし、サーバー側に保存します。認可方式は OAuth 2.0 の `client_credentials` です。
3. クライアントシークレットを再発行した場合は、利用先に保存している値を更新します。利用を終了する場合はクライアントを削除できます。

### アクセストークンをリクエストする

クライアント ID とクライアントシークレットを入力します。フォームは HTTP Basic 認証で `organization:access` トークンを取得します。成功後は「アクセストークンをコピー」を選びます。

スクリプトでは `POST /api/authV2/oauth2/token` に `application/x-www-form-urlencoded` 形式で `grant_type=client_credentials` と `scope=organization:access` を送信します。

生成コードを使う場合は、クライアント ID とシークレットをそれぞれフォーム形式でエンコードし、`:` で連結して Base64 エンコードした値で `{{BASE64_CLIENT_CREDENTIALS}}` を置き換えます。

    },
  }}
/>

### 成功時の応答

以下は HTTP `200 OK` の応答の抜粋です。`expires_in` はトークンの有効期間を秒単位で示します。期限切れになったら、同じ OAuth クライアントで新しいトークンを取得します。

```json
{
  "access_token": "EXAMPLE_ACCESS_TOKEN",
  "token_type": "Bearer",
  "expires_in": 3600,
  "scope": "organization:access"
}
```

| エラー | 確認方法 |
| --- | --- |
| `invalid_client` | クライアント ID、最新のクライアントシークレット、HTTP Basic 認証の形式を確認します。 |
| `invalid_scope` | `scope` に `organization:access` を指定します。 |
| `invalid_grant` | 組織が有効であることを確認し、`client_credentials` を使用します。 |

API キー、クライアントシークレット、アクセストークンは、管理されたサーバー環境に保存してください。

## 最初のリクエストを送信する

組織の API キー、または取得した OAuth アクセストークンを入力してリクエストを送信します。

スクリプトでは、組織の API キーまたはアクセストークンを `Authorization: Bearer <認証情報>` で送信します。`dot_org_` で始まる組織の API キーは `x-api-key` ヘッダーでも送信できます。1 回のリクエストには認証情報を一つだけ指定します。

<ApiPlayground
  endpoint="/api/authV2/organization/software/projects"
  method="GET"
  auth="organization"
/>

HTTP `200` の応答には、組織の Read Pico プロジェクトが含まれます。空の配列が返った場合は、[最初のデバイスソフトウェア ID を作成](/docs/service/open/organization_software/software_ids)できます。HTTP `401` の場合は、組織の API キーを確認するか、アクセストークンを再取得します。HTTP `403` の場合は、組織が有効であることを確認します。
