title: API のレート制限を理解する
new: true
---

API のレート制限は、一定時間内にサーバーが受け付けるリクエスト数の上限です。

同じ API キーで、3 台のデバイスに同時に即時更新をリクエストできます。たとえば、リビングのデバイスにテキストの即時表示をリクエストし、その 1 秒後に画像の即時表示をリクエストすると、2 回目はレート制限に達します。同じデバイスへの即時更新リクエストには、2 秒以上の間隔が必要です。

## リクエストとレート制限を理解する

- **デバイスの即時更新**。即時更新リクエストは、同じデバイスに対して 2 秒に 1 回までです。テキスト、画像、Canvas の即時更新と、次のコンテンツへの切り替えは、この制限を共有します。待ち時間はデバイスごとに計算されます。
- **HTTP リクエスト**。同じクライアント IP から同じパスに送信できるリクエストは、1 秒あたり最大 10 件です。同じグローバル IP を使うプログラムが同じパスにアクセスする場合、この 10 件を共有します。

### 操作ごとに適用される制限

即時更新をリクエストした後の 2 秒間も、デバイスの状態を確認したり、設定を更新したり、あとで表示するコンテンツを保存したりできます。

| 操作 | 即時更新の制限 | HTTP リクエストの制限 |
| --- | --- | --- |
| ループコンテンツを書き込んで即時更新する（既定値は `taskType: "loop"` と `refreshNow: true`） | 対象 | 対象 |
| 次のコンテンツへ切り替える | 対象 | 対象 |
| ループコンテンツの保存のみ（`taskType: "loop"` と `refreshNow: false`） | 対象外 | 対象 |
| 固定コンテンツの保存のみ（`taskType: "fixed"` と `refreshNow: false`） | 対象外 | 対象 |
| デバイス一覧、デバイスの状態、コンテンツ一覧、デバイス設定、タイムゾーンを取得する | 対象外 | 対象 |
| デバイス設定を更新する | 対象外 | 対象 |
| デバイスが設定済みのスケジュールに沿って固定コンテンツを自動表示する | 対象外 | 対象外 |

`refreshNow` はループコンテンツの即時更新だけを制御します。固定コンテンツはデバイスのスケジュールに従うため、保存時に `refreshNow` を省略できます。

たとえば、同じグローバル IP からリビングのデバイスの状態を取得できる回数は 1 秒あたり最大 10 回です。寝室のデバイスの状態取得は別のパスになるため、別に数えます。クエリパラメータが異なっても、同じパスの上限が適用されます。

## 429 が返った場合

HTTP `429 Too Many Requests` は、リクエスト頻度が上限に達し、処理が拒否されたことを示します。レスポンスヘッダーの `Retry-After` が示す秒数だけ待ってから、リクエストを再送してください。たとえば、`Retry-After: 1` の場合は 1 秒待ちます。

デバイスの即時更新制限に達すると、サーバーはコンテンツを保存する前に書き込みを拒否します。待ち時間はレスポンス本文にも含まれます。

```json
{
  "code": "RATE_LIMITED",
  "message": "このデバイスへの更新リクエストが多すぎます。1 秒後にもう一度お試しください。",
  "retryAfter": 1
}
```
