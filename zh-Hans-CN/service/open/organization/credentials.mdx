组织凭据可用于查询、上传和发布本组织的小纸 Pico 软件，也可创建和归档设备软件 ID。组织所有者和管理员可以在「我的组织 → Field Lab → 组织 → 凭据」创建 API 密钥和 OAuth 客户端。

## 创建 API 密钥

1. 在「API 密钥」中选择「创建 API 密钥」，填入名称 `Field Lab Integration`。
2. 从结果中复制密钥，存入服务端的密钥管理工具。完整密钥仅在创建时显示。
3. 需要更换密钥时，先创建替代密钥并更新使用方，再撤销旧密钥。

## 创建 OAuth 客户端

1. 在「OAuth 客户端」中选择「创建 OAuth 客户端」，填入名称 `Field Lab Service`。
2. 复制客户端 ID 和客户端密钥，保存在服务端。这组凭据用于 OAuth 2.0 的 `client_credentials` 授权方式。
3. 重置客户端密钥后，更新服务端保存的密钥。停用客户端时，可以删除该客户端。

### 请求访问令牌

填写客户端 ID 和客户端密钥。表单使用 HTTP Basic 认证，请求 `organization:access` 令牌。成功后可点「复制访问令牌」。

脚本向 `POST /api/authV2/oauth2/token` 发送 `application/x-www-form-urlencoded` 请求体，传入 `grant_type=client_credentials` 和 `scope=organization:access`。

使用生成的代码时，先分别按表单规则编码客户端 ID 和客户端密钥，用 `:` 连接后做 Base64 编码，再替换 `{{BASE64_CLIENT_CREDENTIALS}}`。

### 成功响应

HTTP `200 OK` 响应节选如下。`expires_in` 表示令牌剩余有效秒数。到期后用同一个客户端再次请求。

```json
{
  "access_token": "EXAMPLE_ACCESS_TOKEN",
  "token_type": "Bearer",
  "expires_in": 3600,
  "scope": "organization:access"
}
```

| 错误 | 检查方式 |
| --- | --- |
| `invalid_client` | 检查客户端 ID、最新的客户端密钥和 HTTP Basic 认证格式。 |
| `invalid_scope` | 将 `scope` 设置为 `organization:access`。 |
| `invalid_grant` | 检查组织是否仍有效，并使用 `client_credentials`。 |

API 密钥、客户端密钥和访问令牌只保存在服务端的受控环境中。

## 发送第一个请求

在「组织凭据」中填入 API 密钥或刚取得的 OAuth 访问令牌，然后发送请求。

脚本可用 `Authorization: Bearer <凭据>` 发送组织 API 密钥或 OAuth 访问令牌。组织 API 密钥以 `dot_org_` 开头，也可单独使用 `x-api-key` 请求头。每次只发送一种凭据。

<ApiPlayground
  endpoint="/api/authV2/organization/software/projects"
  method="GET"
  auth="organization"
/>

HTTP `200` 返回本组织的小纸 Pico 项目。空数组时可以[创建第一个设备软件 ID](/docs/service/open/organization_software/software_ids)。遇到 HTTP `401`，请确认使用本组织的 API 密钥，或重新获取访问令牌。遇到 HTTP `403`，请检查组织是否处于可用状态。
