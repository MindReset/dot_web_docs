export const releaseNotesParam = {
  type: "array",
  name: "リリースノートの言語",
  placeholder: "言語を選択",
  example: ["ja-JP"],
  options: Object.entries(releaseNoteLocales).map(([value, label]) => ({ value, label })),

`POST /api/authV2/device/firmware/query` で、公開済みのデバイスソフトウェアを照会できます。ログインや API キーは不要です。組織ソフトウェアを照会するには、[デバイスソフトウェア ID](/docs/service/open/organization_software/software_ids) と、プロジェクトに紐付くデバイス情報を指定します。

## デバイス ID で照会する

デバイス ID での照会を推奨します。デバイスの MAC アドレスからコロンを取り除き、英字を大文字にします。たとえば、`02:ab:cd:ef:12:34` は `02ABCDEF1234` になります。

変換したデバイス ID をリクエストボディの `id` に指定し、プロジェクトの `firmwareId` も送信します。サーバーはデバイス ID からシリーズ、モデル、ハードウェアバージョンを取得し、`status` に応じて公開チャネルを選びます。

<ApiPlayground
  endpoint="/api/authV2/device/firmware/query"
  method="POST"
  bodyParams={{
    id: { type: "string", name: "デバイス ID", required: true, example: "02ABCDEF1234" },
    firmwareId: { type: "string", name: "デバイスソフトウェア ID", required: true, example: "000000000000000000000101" },
    status: {
      example: "TESTING",
      type: "select",
      name: "公開チャネル",
      default: "TESTING",
      options: [
        { value: "ALPHA", label: "内部テスト" },
        { value: "TESTING", label: "公開テスト" },
        { value: "RELEASED", label: "正式版" },
      ],
    },
    currentVersion: { type: "string", name: "インストール済みのバージョン", default: "1.1.0", example: "1.1.0" },
    version: { type: "string", name: "指定バージョン" },
    releaseNotes: releaseNotesParam,
  }}
/>

## 応答例

HTTP `200 OK`。この例では `releaseNotes: ["ja-JP"]` を送信し、`1.2.0-beta.1` が選ばれています。インストール済みのバージョンより新しいため、`needUpdate` は `true` です。

```json
{
  "series": "read",
  "model": "read_0",
  "edition": 1,
  "status": "TESTING",
  "firmwareId": "000000000000000000000101",
  "version": "1.2.0-beta.1",
  "needUpdate": true,
  "updateVersion": "1.2.0-beta.1",
  "releaseNotes": [
    { "locale": "ja-JP", "content": "スリープから復帰した後の画面更新を安定させました。" }
  ],
  "ota": {
    "downloadUrl": "https://dot.mindreset.tech/download/AwAAAAAAAAAAAAABAwAAAAA",
    "size": 1176976,
    "sha256": "a4b13eb3a234a0446faeed2e1d07a22f52bf06b40b00e22f219e15211eed6b07"
  }
}
```

- `version` と `updateVersion` は、今回選ばれたバージョンを示します。
- `needUpdate` が `true` になるのは、選ばれたバージョンが `currentVersion` より新しい場合です。インストール済みバージョンを省略すると、バージョン情報と `needUpdate: false` が返ります。
- 選択されたバージョンに OTA ファイルがない場合、`ota` は `null` です。ファイルがある場合は `ota.downloadUrl` に GET リクエストを送り、HTTP 302 リダイレクトをたどります。署名付き URL の有効期間は最長 3 分です。[OTA ファイルのダウンロードと検証](/docs/service/open/organization_software/download)を参照してください。

<TypeTable
  type={{
    releaseNotes: {
      type: 'array',
      description: "選ばれたバージョンのリリースノート。本文のある言語が指定順に返り、該当する本文がなければ空の配列が返ります。デバイスが最新版でも取得できます。",
      items: {
        locale: {
          type: 'string',
          description: "項目の言語コード。",
        },
        content: {
          type: 'string',
          description: "リリースノートの全文。新規提出時は 1 言語あたり 20,000 文字までです。",
        },
      },
    },

/>

Web サイトや書き込みツールで一括書き込みイメージや分割書き込みパッケージを提供する場合は、[組織のバージョン一覧または詳細](/docs/service/open/organization_software/organization_versions)からダウンロード URL を取得できます。

`firmwareId` を省略して公式ソフトウェアを照会すると、`ota` には従来の `ota.path` とダウンロード用の `ota.downloadUrl` の両方が含まれます。既存のデバイスでは、引き続き `https://os-cdn.mindreset.tech/` を基準に相対パス `ota.path` を解決できます。

`GET /api/authV2/device/ota` は非推奨です。稼働中のデバイスでは引き続き利用できます。新規連携では、このページの POST リクエストと `ota.downloadUrl` を使用してください。

## トラブルシューティング

リクエスト本文が無効な場合、HTTP `400` の応答に次のメッセージが含まれます。

```json
{
  "message": "Invalid firmware query."
}
```

| HTTP ステータス | 確認方法 |
| --- | --- |
| `400` | デバイス情報、チャネル、SemVer の形式を確認します。 |
| `404` | デバイス ID に対応する情報があるか確認するか、リクエストのモデル情報を確認します。ソフトウェアに紐付くデバイス、組織の利用状況、対象チャネルとバージョンの公開状況も確認します。 |
| `429` | 同一 IP からは毎秒 10 件まで照会できます。リクエスト頻度を下げて再試行してください。 |
| `500` | 照会を完了できませんでした。時間を置いて再試行してください。 |

配信用サーバーからは、[組織の認証情報で公開済みのバージョンを照会](/docs/service/open/organization_software/organization_version_query)できます。下書きや審査状況を調べるには、[バージョンの一覧と詳細](/docs/service/open/organization_software/organization_versions)を使います。
