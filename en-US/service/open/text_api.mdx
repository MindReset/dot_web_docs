## Quick Guide

### Prerequisites

1. Make sure you have <Link href="/docs/service/studio/api/get_api">retrieved and saved your API key</Link> in the Dot. App;
2. Make sure you own at least one device and have <Link href="/docs/service/studio/api/get_device_id">obtained its device serial number</Link>;
3. Make sure your device is connected to power;
4. Make sure your device is connected to the network;
5. Make sure you've added the Text API content to the device **loop or fixed list** from the Content Studio in the Dot. App.

<Callout type="info" title="What Text API is for">
	Text API turns reminders, notes, signatures, and small icons into a readable device card. Use it for automation messages, lightweight notifications, daily excerpts, or any short text you want to see on the device.
</Callout>

<Callout type="info" title="Choose a content list and display timing">
	Choose the loop list or fixed list; the loop list is used by default. A task identifier targets an item only in the selected list. Without an identifier, the first Text API item in that list is updated.

	Enable immediate display for loop content to request a screen update while the device is online. A sleeping device on battery retrieves saved content after automatic wake. Fixed content follows the times configured in Dot. App: even the item currently on screen waits for the next scheduled refresh. The API preserves its time settings. Read <Link href="/docs/quote_0/faq/refresh_timing">Timing</Link> for details.
</Callout>

<Callout type="info" title="About icon input">
	An icon is optional. Send PNG Base64 data or a full HTTP(S) image URL. PNG Base64 may be bare Base64 or include the `data:image/png;base64,` prefix; the decoded payload must be no larger than 1MB. A 40px×40px icon is recommended. Remote icon URLs must be anonymously accessible, require no authentication or special Referer, be no longer than 2048 characters, return a response body no larger than 3MB, and return `image/*` content directly.
</Callout>

<Callout type="info" title="Test icon URLs for debugging">
	The following URLs are currently anonymously accessible and return image content that can be used for the Text API `icon` field:

	- `https://placehold.co/40x40/png`
	- `https://httpbin.org/image/png`

	If you want to verify your own icon URL first, run:

	```bash
	curl -I 'https://your-icon-url'
	```

	In most cases, you should confirm at least:

	- The HTTP status code is `200`
	- The `Content-Type` is `image/*`, such as `image/png` or `image/jpeg`
</Callout>

### Update content in the fixed list

Query the fixed list, find the `TEXT_API` item in the response, and use its `key` as `taskKey`:

```bash
curl 'https://dot.mindreset.tech/api/authV2/open/device/{{deviceId}}/fixed/list' \
  -H 'Authorization: Bearer dot_app_{{apiKey}}'
```

Call the same write endpoint with `taskType: "fixed"` and that `taskKey` at the top level. This request only saves the content; `refreshNow: true` does not display or refresh fixed content early:

```bash
curl -X POST 'https://dot.mindreset.tech/api/authV2/open/device/{{deviceId}}/text' \
  -H 'Authorization: Bearer dot_app_{{apiKey}}' \
  -H 'Content-Type: application/json' \
  -d '{
  "taskType": "fixed",
  "taskKey": "{{taskKey}}",
  "refreshNow": true,
  "title": "Today",
  "message": "The meeting moved to 10:30."
}'
```

### Response Example

This is an example response for immediate display of loop content.

```json
{
	"message": "Device ABCD1234ABCD text API content switched."
}
```

### Line Breaks and Tabs

Text API preserves line breaks and tabs in `message`.

- Use `\n` for a new line and `\t` for a tab in the JSON request body.
- If your JSON is embedded inside another string literal, such as shell, JavaScript, Python, templates, or tool configs, you often need to write `\\n` and `\\t` in the outer string so the final JSON still contains `\n` and `\t`.
- If you want the device to literally display the characters `\n` or `\t`, make the final JSON payload contain `\\n` or `\\t`.

```json
{ "message": "Line 1\n\tIndented line 2" }
{ "message": "Show literal \\n and \\t" }
```

### Status Codes

| HTTP status | Meaning                 | Description                                                       |
| :---------- | :---------------------- | :---------------------------------------------------------------- |
| `200`       | Success                 | Text API content switched / Data updated but content not switched |
| `400`       | Invalid parameters      | Invalid content list type<br/>Invalid icon format |
| `403`       | Forbidden               | You do not have permission to operate this device                 |
| `404`       | Not found               | Device not found or not registered<br/>Matching API content is missing from the selected list, or the task identifier does not match a Text API item in that list |
| `500`       | Device response failure | Failed to switch Text API content                                 |

### Troubleshoot list selection and display timing

- `400`: use only `loop` or `fixed` for `taskType`.
- `404`: ensure the request uses the same `taskType` as the list query and a `taskKey` from a matching API item in that list. Omitting `taskType` selects the loop list.
- Fixed content was saved but the screen did not change: check its time settings in Dot. App and wait for the next scheduled refresh. `refreshNow: true` does not immediately refresh fixed content.
