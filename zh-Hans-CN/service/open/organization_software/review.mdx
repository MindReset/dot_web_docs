[提交正式版](/docs/service/open/organization_software/publish)后，可以在组织的「软件」里打开版本查看审核进度，也可以用组织凭据[查询版本详情](/docs/service/open/organization_software/organization_versions)。审核通过后，正式版会自动生效。

## 在网页上处理审核

- 正式版草稿点击「提交审核」后变为**待审核**。需要改动时可「撤回审核」，回到草稿。
- 状态为**需修改**时，查看审核意见，点「修改后重新提交」。可编辑说明、保留或替换软件文件，再提交同一个版本。

## 用组织 API 重新提交

正式版进入 `rejected` 状态时，先[查询版本详情](/docs/service/open/organization_software/organization_versions)读取 `reviewReason`、`id` 和本轮 `reviewId`。准备上传时沿用 `firmwareId` 和 `version`，将详情的 `id` 填入 `revision.versionId`，并传入 `revision.reviewId`。

`revision.retainFiles` 是要保留的文件类型数组，例如 `["ota", "merged"]`。在 `artifacts` 中提供新增或替换的文件。传 `[]` 表示全部使用新文件，提交的版本至少需要一个文件。只保留已有文件时，`uploads` 为空对象，直接确认即可。

这次的 `releaseNotes` 会替换原版本的发布说明。需要保留的语言也要随请求提交。确认后，响应以原版本 `id` 返回 `state: "pending"` 和新的 `reviewId`，重新进入正式版审核。

拿到新的 `uploadId` 后，按[上传步骤](/docs/service/open/organization_software/upload)上传 `uploads` 中的文件，再确认上传。如果收到 `409 ORGANIZATION_SOFTWARE_STATE_CHANGED`，先重新查询版本详情，再使用当前的 `reviewId`。
