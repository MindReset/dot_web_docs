Use `POST /api/authV2/device/firmware/query` to query live device software. This endpoint requires no login or API key. To query organization software, send its [device software ID](/docs/service/open/organization_software/software_ids) and the device identity bound to that software.

## Query by device ID

Querying by device ID is recommended. Read the device’s MAC address, remove the colons, and convert its letters to uppercase. For example, `02:ab:cd:ef:12:34` becomes `02ABCDEF1234`.

Send the resulting device ID as `id` in the request body along with the project’s `firmwareId`. The server looks up the device’s series, model, and hardware edition by ID and uses `status` to select the release channel.

## Response example

HTTP `200 OK`. The selected version is `1.2.0-beta.1`, which is newer than the installed version, so `needUpdate` is `true`.

```json
{
  "series": "read",
  "model": "read_0",
  "edition": 1,
  "status": "TESTING",
  "firmwareId": "000000000000000000000101",
  "version": "1.2.0-beta.1",
  "needUpdate": true,
  "updateVersion": "1.2.0-beta.1",
  "ota": {
    "downloadUrl": "https://dot.mindreset.tech/download/AwAAAAAAAAAAAAABAwAAAAA",
    "size": 1176976,
    "sha256": "a4b13eb3a234a0446faeed2e1d07a22f52bf06b40b00e22f219e15211eed6b07"
  }
}
```

- `version` and `updateVersion` identify the selected version.
- `needUpdate` is `true` only when the selected version is newer than `currentVersion`. Omitting the installed version still returns the version metadata with `needUpdate` set to `false`.
- `ota` is `null` when the selected version has no OTA file. If `ota` is present, send a GET request to `ota.downloadUrl` and follow the HTTP 302 redirect to a signed URL valid for three minutes. See [Download and update](/docs/service/open/organization_software/download).

When you omit `firmwareId` to query official software, `ota` includes both the legacy `ota.path` and the authorized `ota.downloadUrl`. Existing devices can continue to resolve the relative `ota.path` against `https://os-cdn.mindreset.tech/`.

## Troubleshooting

For an invalid request body, the HTTP `400` response includes this message.

```json
{
  "message": "Invalid firmware query."
}
```

| HTTP status | What to check |
| --- | --- |
| `400` | Check the device identity, channel, and SemVer syntax. |
| `404` | Check that a device record exists for the ID or verify the model details in the request. Check the software’s device binding, the organization’s availability, and whether a matching version is live in the requested channel. |
| `429` | This endpoint allows 10 requests per second per IP. Reduce the request rate and retry. |
| `500` | The query could not be completed. Retry later. |

For a release service, you can also [query published versions with organization credentials](/docs/service/open/organization_software/organization_version_query). For drafts or review progress, use the [version list and details](/docs/service/open/organization_software/organization_versions).
