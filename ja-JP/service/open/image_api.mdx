## クイックガイド

### 必要条件

1. Dot. アプリで<Link href="/docs/service/studio/api/get_api">API キーを取得して保存</Link>していること
2. 自分のデバイスが少なくとも 1 台あり、<Link href="/docs/service/studio/api/get_device_id">デバイスのシリアル番号</Link>を取得していること
3. デバイスが電源に接続されていること
4. デバイスがネットワークに接続されていること
5. Dot. アプリの創造所から「画像 API」コンテンツをデバイスの**ループリストまたは固定リスト**に追加していること

<Callout type="info" title="Image API の用途">
	Image API は、ポスター、スクリーンショット、ダッシュボード、お気に入りの画像をデバイスに送ります。すでに完成したビジュアルを、そのまま表示したい場合に向いています。
</Callout>

<Callout type="info" title="コンテンツリストと表示タイミング">
	更新するコンテンツをループリストまたは固定リストから選びます。指定しない場合はループリストを使用します。タスク識別子は選択したリスト内だけで検索し、省略時はそのリストの最初の対応する API コンテンツを更新します。

	ループリストでは即時表示を有効にすると、オンラインのデバイスへ更新を要求します。バッテリー駆動でスリープ中の場合は保存し、自動起動時に取得します。固定リストでは Dot. App の時間設定に従い、現在表示中でも次回の予定された更新を待ちます。API は時間設定を変更しません。詳しくは<Link href="/docs/quote_0/faq/refresh_timing">時間の仕組み</Link>をご覧ください。
</Callout>

<Callout type="info" title="画像入力について">
	表示する画像を PNG Base64 データまたは完全なオンライン `http(s)` 画像 URL で送信します。PNG Base64 は裸の Base64、または `data:image/png;base64,` プレフィックス付きの形式を使用でき、デコード後のサイズは最大 3MB です。リモート画像 URL は匿名で直接アクセスでき、認証や特別な Referer を必要とせず、URL 長は 2048 文字以内、レスポンス本文は最大 3MB で、`image/*` を直接返す必要があります。
</Callout>

<Callout type="info" title="デバッグ用のテスト画像 URL">
	以下の URL は現時点で匿名アクセス可能で、Image API で利用できる画像コンテンツを返します。

	- `https://placehold.co/600x400/png`
	- `https://httpbin.org/image/png`

	自分の画像 URL が使えるか先に確認したい場合は、次を実行してください。

	```bash
	curl -I 'https://your-image-url'
	```

	通常は少なくとも次の 2 点を確認してください。

	- HTTP ステータスコードが `200`
	- `Content-Type` が `image/*` であること。例: `image/png`、`image/jpeg`
</Callout>

### 固定リストのコンテンツを更新する

固定リストを取得し、レスポンスから `IMAGE_API` コンテンツを探して、その `key` を `taskKey` として使います。

```bash
curl 'https://dot.mindreset.tech/api/authV2/open/device/{{deviceId}}/fixed/list' \
  -H 'Authorization: Bearer dot_app_{{apiKey}}'
```

同じ書き込み API に、`taskType: "fixed"` と取得した `taskKey` をリクエストのトップレベルで送ります。次のリクエストは保存のみを行い、`refreshNow: true` でも固定コンテンツを早めに表示・更新しません。

```bash
curl -X POST 'https://dot.mindreset.tech/api/authV2/open/device/{{deviceId}}/image' \
  -H 'Authorization: Bearer dot_app_{{apiKey}}' \
  -H 'Content-Type: application/json' \
  -d '{
  "taskType": "fixed",
  "taskKey": "{{taskKey}}",
  "refreshNow": true,
  "image": "https://placehold.co/600x400/png"
}'
```

## 画像ディザリング

画像ディザリングは、特定のアルゴリズムで視覚ノイズを低減し、見た目を滑らかにする処理です。Floyd-Steinberg、Atkinson、Sierra などが代表例です。電子ペーパーでは階調の遷移が自然になり、白黒表示の質が向上します。

画像 API では、**`ditherType`を指定しない場合**、誤差拡散ディザの Floyd-Steinberg をデフォルトで使用します。パラメータで無効化や種類・アルゴリズムの変更が可能です。

### ディザリングを有効化

#### 誤差拡散ディザ（デフォルト）

誤差拡散ディザは、各ピクセルの誤差を周囲のピクセルに分配することで視覚ノイズを低減し、見た目を滑らかにする処理です。このアルゴリズムは画像中のコントラストの高い領域を効果的に処理し、階調間の遷移をより自然にします。通常、点的分布が自然で、明らかな規則的なグリッドパターンがなく、詳細な表現が豊かで、階調の遷移が滑らかな効果を示します。

#### 有序ディザ（Ordered）

有序ディザは、規則的なディザ行列を画像ピクセルに適用することで階調やカラーの近似を実現するアルゴリズムです。誤差拡散ディザとは異なり、有序ディザはピクセル誤差に基づいて周囲ピクセルの値を動的に調整するのではなく、あらかじめ定義された固定のディザ行列を画像全体に周期的に重ね合わせます。この方法は大面積のカラーブロックやバンディング現象を効果的に軽減し、視覚的により均一な点阵分布を実現します。ディザ行列の周期性により、有序ディザが生成する画像は通常、一定の規則性とグリッド感を伴います。

### レスポンスコード

| HTTP ステータス | 意味             | 説明                                                                                                               |
| :-------------- | :--------------- | :----------------------------------------------------------------------------------------------------------------- |
| `200`           | 成功             | デバイスの画像 API コンテンツを切り替え／データ更新（ただし表示は切り替わっていない）                              |
| `400`           | パラメータ不正   | コンテンツリストの種類が無効／デバイス ID の欠如または形式不正／画像形式が無効／画面の枠色が無効／ディザ種別またはアルゴリズムが無効 |
| `403`           | 権限不足         | 当該デバイスを操作する権限がありません                                                                             |
| `404`           | 未検出           | デバイスが存在しない・未登録／選択したリストに対応する API コンテンツがない、またはタスク識別子がそのコンテンツを示していない                                           |
| `500`           | デバイス応答失敗 | 画像 API コンテンツの切替に失敗                                                                                    |

### リストと表示タイミングの確認

- `400`：`taskType` には `loop` または `fixed` を指定してください。
- `404`：一覧取得と書き込みで同じ `taskType` を使い、そのリスト内の対応する API コンテンツの `taskKey` を指定してください。`taskType` の省略時はループリストを選択します。
- 固定コンテンツの保存後も画面が変わらない場合：Dot. App の時間設定を確認し、次回の予定された更新を待ってください。`refreshNow: true` でも固定コンテンツは即時更新されません。
