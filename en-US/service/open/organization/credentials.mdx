Use organization credentials to query, upload, and publish your team's Read Pico software and to create or archive device software IDs. Owners and admins can create API keys and OAuth clients under **My organizations → Field Lab → Organization → Credentials**.

## Create an API key

1. Under **API keys**, select **Create API key** and name it `Field Lab Integration`.
2. Copy the full key and store it in your server-side secrets manager. The full key is displayed once, when you create it.
3. To replace a key, create a new one and update its consumers before revoking the old key.

## Create an OAuth client

1. Under **OAuth clients**, select **Create OAuth client** and name it `Field Lab Service`.
2. Copy the client ID and client secret and store them on your server. These credentials use the OAuth 2.0 `client_credentials` grant.
3. After resetting the client secret, update the secret stored by your service. Delete the client when you retire it.

### Request an access token

Enter your client ID and client secret. The form uses HTTP Basic authentication to request a token with `organization:access`. Select **Copy access token** after a successful response.

Scripts call `POST /api/authV2/oauth2/token` with an `application/x-www-form-urlencoded` body containing `grant_type=client_credentials` and `scope=organization:access`.

In the generated code, replace `{{BASE64_CLIENT_CREDENTIALS}}` with the Base64 encoding of the form-encoded client ID and secret joined by `:`.

### Successful response

The HTTP `200 OK` response below shows `expires_in`, the token lifetime in seconds. Request another token with the same OAuth client when it expires.

```json
{
  "access_token": "EXAMPLE_ACCESS_TOKEN",
  "token_type": "Bearer",
  "expires_in": 3600,
  "scope": "organization:access"
}
```

| Error | What to check |
| --- | --- |
| `invalid_client` | Check the client ID, the latest client secret, and the HTTP Basic authentication format. |
| `invalid_scope` | Set `scope` to `organization:access`. |
| `invalid_grant` | Check that the organization is active and use `client_credentials`. |

Keep API keys, client secrets, and access tokens in a controlled server-side environment.

## Send your first request

Enter your organization API key or the OAuth access token you just obtained, then send the request.

Scripts send the API key or access token in `Authorization: Bearer <credential>`. An organization API key starts with `dot_org_` and can also be sent on its own in `x-api-key`. Send one credential per request.

<ApiPlayground
  endpoint="/api/authV2/organization/software/projects"
  method="GET"
  auth="organization"
/>

HTTP `200` returns your organization's Read Pico projects. If the array is empty, [create your first device software ID](/docs/service/open/organization_software/software_ids). For HTTP `401`, check the organization key or get a new access token. For HTTP `403`, check that the organization is active.
