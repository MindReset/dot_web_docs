デバイスから公開済みバージョンを照会し、OTA ファイルをダウンロードして検証した後、ファームウェアから更新できます。ウェブサイトでは初回インストールや復旧用の有線書き込みファイルも配布できます。

## OTA 更新の手順

<Steps>
<Step>
### バージョンを照会する

ソフトウェア ID の `firmwareId` とインストール済みバージョンの `currentVersion` を指定し、[デバイスからバージョンを照会](/docs/service/open/organization_software/version_query)します。通常の更新では、`needUpdate` が `true` で、`ota` にファイル情報が含まれる場合にダウンロードします。

</Step>
<Step>
### 302 をたどってダウンロードする

`ota.downloadUrl` に `GET` を送り、HTTP `302` の `Location` が示す CDN の署名付き URL へ移動します。成功した応答からバイナリファイルを取得します。cURL では `--location` を指定します。

</Step>
<Step>
### ファイルを検証する

照会結果のシリーズ、モデル、ハードウェアバージョンがデバイスと一致することを確認します。ダウンロード完了後、ファイルのバイト数と SHA-256 を `ota.size` と `ota.sha256` に照らし合わせます。

</Step>
<Step>
### 更新をインストールする

検証に成功したら、ファームウェアの OTA 更新処理でファイルをインストールします。

</Step>
</Steps>

## 署名の有効期限と再試行

バージョンの配布中は、`ota.downloadUrl` にリクエストするたびに新しい CDN の署名付き URL が発行されます。`302` 応答の `Location` に含まれる URL は、発行から**最大 3 分間有効**です。有効期限内に CDN へのダウンロードリクエストを開始してください。

CDN はリクエストを受け取った時点で署名を検証します。有効期限内に開始し、転送が続いているダウンロードは、通常 3 分を超えても完了できます。再試行、途中からの再開、別の範囲の取得は新しいリクエストになります。署名の期限が切れた場合は、元の `ota.downloadUrl` にアクセスして新しい URL を取得します。

続きからダウンロードするには、CDN に `Range` リクエストを送ります。応答が `206 Partial Content` で、`Content-Range` の開始位置が保存済みのバイト数と一致する場合に、保存したファイルに追記できます。`200 OK` が返った場合は、ファイル全体で置き換えます。

## 応答例

この例では `Desk Clock` の公開テスト版をダウンロードします。リダイレクト先の HTTP `200 OK` 応答には、OTA ファイルのバイナリデータが含まれます。

```http
HTTP/1.1 302 Found
Location: https://cdn.mindreset.tech/path/to/ota?sign=example
Cache-Control: private, no-store

HTTP/1.1 200 OK
Content-Type: application/octet-stream
Content-Length: 1176976
Content-Disposition: attachment; filename*=UTF-8''desk-clock-1.2.0-beta.1.bin
```

この例では `1176976` バイトで、SHA-256 は `a4b13eb3a234a0446faeed2e1d07a22f52bf06b40b00e22f219e15211eed6b07` です。実際の照会で返された値を使ってください。

## トラブルシューティング

- 署名の有効期限が切れて CDN が HTTP `403` を返した場合は、`ota.downloadUrl` に再度アクセスします。
- ダウンロード用のエンドポイントが HTTP `404` を返した場合は、バージョンと組織が引き続き利用可能か確認します。バージョンの配布が停止または取り消された場合や、組織が利用できない場合は署名付き URL が発行されません。同じソフトウェア ID とチャネルで再度照会し、更新が必要か判断します。
- HTTP `503` が返った場合は、時間をおいて再試行します。

## 有線書き込み用ファイルをダウンロードする

初回のインストールや復旧用に、公開済みバージョンの一括書き込みイメージや分割書き込みパッケージを配布できます。

- [バージョン一覧](/docs/service/open/organization_software/organization_versions#バージョンを一覧表示する)を開きます。デバイスソフトウェア ID を入力し、公開チャネルで「正式リリース」、バージョンの状態で「公開済み」を選びます。`items` 内の対象バージョンから `downloads` を取得します。
- バージョン ID がわかっている場合は、[バージョン詳細](/docs/service/open/organization_software/organization_versions#バージョンと審査状況を確認する)でデバイスソフトウェア ID とバージョン ID を入力し、応答の `downloads` を取得します。

| ダウンロード項目 | ファイル |
| --- | --- |
| `downloads.merged` | 一括書き込みイメージ（`.bin`）。 |
| `downloads.archive` | 分割書き込みパッケージ（`.tgz` または `.tar.gz`）。 |
| `downloads.ota` | OTA アプリケーションファームウェア（`.bin`）。 |

`downloads` には、そのバージョンで提供されているファイルが含まれます。`artifacts.merged` など、対応する `artifacts` 項目の `size` と `sha256` でダウンロードしたファイルを検証します。

ダウンロードボタンには、応答に含まれる Dot. URL を設定します。利用者は組織の認証情報なしで HTTP `302` をたどってダウンロードできます。リダイレクト先の CDN URL が期限切れになったら、元の URL に再度アクセスします。

`Field Lab` の「ソフトウェア」でバージョン詳細を開き、ソフトウェアファイルの一覧から取得することもできます。
