title: 了解 API 限速
new: true

API 限速规定服务端在一段时间内最多接受多少次请求。

用同一个 API 密钥管理三台设备时，可以同时给三台设备发送立即刷新请求。假设你刚请求客厅的设备立即显示一条文字，过了 1 秒又让它立即显示一张图片。第二次请求会触发限速，因为这台设备的两次立即刷新请求至少要间隔 2 秒。

## 了解请求与限速

- **设备立即刷新**。同一台设备每 2 秒最多接受一次立即刷新请求。文字、图片、画布的立即刷新与「切换到下一条」共用这 2 秒的间隔。不同设备各自计时。
- **HTTP 请求**。同一客户端 IP 对同一路径每秒最多发送 10 次请求。共用一个公网出口 IP 的程序访问同一路径时，共用这 10 次。

### 各项操作计入哪些限速

刚请求一台设备立即刷新后的 2 秒内，仍可以查询它的状态、更新设置或只保存内容。

| 操作 | 设备立即刷新限速 | HTTP 请求限速 |
| --- | --- | --- |
| 写入循环内容并请求立即刷新（`taskType: "loop"`，`refreshNow: true`，均为默认值） | 计入 | 计入 |
| 切换到下一条 | 计入 | 计入 |
| 只保存循环内容（`taskType: "loop"`，`refreshNow: false`） | 不计入 | 计入 |
| 只保存固定内容（`taskType: "fixed"`，`refreshNow: false`） | 不计入 | 计入 |
| 查询设备列表、设备状态、内容列表、设备设置或时区 | 不计入 | 计入 |
| 更新设备设置 | 不计入 | 计入 |
| 设备按设定的日程自行显示固定内容 | 不计入 | 不计入 |

`refreshNow` 只控制循环内容是否立即刷新。固定内容始终按设备日程显示，可以省略 `refreshNow`。

例如，从同一个公网 IP 查询客厅设备的状态，每秒最多 10 次。查询卧室设备的状态走另一条路径，另算 10 次。同一路径的请求即使查询参数不同，也合并计数。

## 收到 429 怎么办

HTTP `429 Too Many Requests` 表示这次请求因频率过高而被拒绝。按 `Retry-After` 响应头给出的秒数等待，再重新发送请求。例如，`Retry-After: 1` 表示等 1 秒。

触发设备立即刷新限速时，服务端会在保存内容前拒绝这次写入。响应正文也会提供等待时间。

```json
{
  "code": "RATE_LIMITED",
  "message": "这台设备的刷新请求过于频繁，请在 1 秒后重试。",
  "retryAfter": 1
}
```
