[正式版を審査に提出](/docs/service/open/organization_software/publish)した後は、組織の「ソフトウェア」からバージョンを開いて進捗を確認できます。組織の認証情報で[バージョンの詳細を取得](/docs/service/open/organization_software/organization_versions)することもできます。審査を通過すると正式版は自動で公開されます。

## ウェブサイトで審査に対応する

- **審査待ち**。正式版の下書きから「審査に提出」を選ぶと、この状態になります。取り下げると下書きに戻ります。
- **要修正**。審査コメントを確認し、「修正して再提出」を選びます。リリースノートを編集し、ファイルを保持または差し替えて同じバージョンを提出できます。

## 組織 API で再提出する

正式版が `rejected` になった場合は、[バージョンの詳細](/docs/service/open/organization_software/organization_versions)で `reviewReason`、`id`、今回の `reviewId` を確認します。元の `firmwareId` と `version` でアップロードを準備します。詳細の `id` を `revision.versionId` に、今回の審査 ID を `revision.reviewId` に指定します。

`revision.retainFiles` には保持するファイルの種類を配列で指定します。たとえば `["ota", "merged"]` です。追加・差し替え用のファイルは `artifacts` に指定します。すべて差し替える場合は `[]` を指定します。提出するバージョンにはファイルが一つ以上必要です。既存ファイルだけを使う場合は `uploads` が空のオブジェクトになるので、そのまま完了に進めます。

今回の `releaseNotes` は元のリリースノート全体を置き換えます。保持する言語の本文も再送してください。完了すると、元のバージョン `id` と `state: "pending"`、新しい `reviewId` が返り、再審査に進みます。

新しい `uploadId` を受け取ったら、[アップロード手順](/docs/service/open/organization_software/upload)に従って `uploads` のファイルをアップロードし、完了リクエストを送ります。`409 ORGANIZATION_SOFTWARE_STATE_CHANGED` が返った場合は、詳細を取得し直し、現在の `reviewId` を使います。
