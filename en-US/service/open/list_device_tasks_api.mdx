## Quick Guide

### Prerequisites

1. Make sure you have <Link href="/docs/service/studio/api/get_api">retrieved and saved your API key</Link> in the Dot. App;

### Endpoint

`/api/authV2/open/device/:deviceId/:taskType/list`

### Method

### Request Schema

This interface does not require a request body, only an API key in the request header.

- `deviceId`: device serial number
- `taskType`: required; `loop` (loop list) or `fixed` (fixed list)

To update API content, use the returned `key` as `taskKey` and send the same `taskType` at the write request top level. For example, update an item from `/fixed/list` with `taskType: "fixed"`. Omitting `taskType` in a write selects the loop list; the fixed list is not searched automatically.

### Response Schema

The response is an array of content items.

- `type`: content type (`TEXT_API` / `IMAGE_API` / `CANVAS_API` / `GENERAL`)
- `key`: content identifier (can be `null`)
- Other fields: the content input payload (varies by content type)

### Status Codes

| code  | Meaning      | Description                         |
| :---- | :----------- | :---------------------------------- |
| `200` | Success      | Successfully retrieved content list |
| `401` | Unauthorized | Invalid or expired API key          |
| `500` | Server Error | Internal server error               |
